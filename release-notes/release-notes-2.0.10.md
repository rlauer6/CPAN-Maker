# CPAN::Maker 2.0.10 Release Notes

**Released:** Mon Sep 14 2026  
**Author:** Rob Lauer \<rclauer@gmail.com\>

---

## Overview

Version 2.0.10 introduces a new `CPAN::Maker::Role::Provides` role
that encapsulates all `provides`-related logic previously scattered
across `CPAN::Maker`, improves `provides` file handling throughout the
build pipeline, and delivers several Makefile robustness fixes.

---

## New Features

### `CPAN::Maker::Role::Provides` — New Role

- All `provides` handling has been extracted into a dedicated role:
  `lib/CPAN/Maker/Role/Provides.pm`
- `CPAN::Maker` now composes this role via `with
  'CPAN::Maker::Role::Provides'`
- The role exposes:
  - `get_provides` — reads and resolves a `provides` file to a hash of modules with file and version metadata
  - `write_provides` — writes a `provides` file from a list of module entries
  - `create_provides` — scans a built `lib/` directory and generates a `provides` file automatically

---

## Changes

### `CPAN::Maker` (`lib/CPAN/Maker.pm.in`)

- **`use parent qw(CLI::Simple)`** moved earlier in the file (before
  `use_log4perl`) to correct load order
- **`cmd_build`**: the `provides` file is no longer deleted from the
  project root after being copied to the build directory, preventing
  unintended removal during iterative builds
- **`get_provides`**: removed from this module — now provided by
  `CPAN::Maker::Role::Provides`
- **`write_provides`**: removed from this module — now provided by
  `CPAN::Maker::Role::Provides`
- **`_write_provides`**: removed (internal helper, superseded by the
  role)
- **`write_makefile`**:
  - `provides` entries in `META_MERGE` now include version strings
    (format: `Module::Name X.Y.Z`)
  - `BUILD_REQUIRES` defaults (`ExtUtils::MakeMaker => 6.64`,
    `File::ShareDir::Install => 0`) are now applied via a hash merge
    rather than being hardcoded inline in the heredoc, making them
    overridable by a project's `build-requires` file
  - `BUILD_REQUIRES` and `PREREQ_PM` Dumper output now has `@N`
    version notation normalised to `== N`
- **`parse_buildspec`**: calls `write_provides` using the new
  named-argument interface from the role
- **`stage_distribution`**:
  - The inline `find`-loop that accumulated `.pm` files for `provides`
    has been replaced with a call to `create_provides` from the new
    role, for consistency and correctness
  - Minor style cleanup: path-prefix conditions converted to `if` blocks for readability

### Makefile

- `PACKAGE_VERSION` exported alongside `MODULE_NAME` for use in
  template resolution
- `PERL5LIB` is now prepended with `$(pwd)/local/lib/perl5` when
  invoking `cpan-maker`, ensuring locally installed dependencies are
  found during distribution builds
- `$(MODULE_PATH).in` recipe: `gen-vars-file` is now called before the
  `tmpl` lookup, fixing variable availability during stub generation
- New `provides` target: builds `.pm` files (with syntax checking off)
  then runs `$(BOOTSTRAPPER) provides` to generate the `provides` file
  from source
- `test-requires.raw` recipe:
  - Now depends on `provides` as well as `$(TESTS)`
  - Uses a temporary file (`test-requires.raw.tmp`) and `comm -23` to
    subtract any modules listed in `provides` from the test dependency
    scan, avoiding false test-only dependency entries for modules
    provided by the distribution itself
- `extra-files` is now generated by `$(BOOTSTRAPPER) extra-files`
  (replacing the previous inline `awk` logic)
- `extra-files.mk` now depends on `extra-files` rather than
  `buildspec.yml` directly
- `-include extra-files.mk` is now guarded by `ifeq
  ($(BOOTSTRAP_BUILD),)` to prevent circular dependency issues during
  bootstrap builds
- `provides` removed from the `CLEANFILES` list (it is now a
  persistent build artifact)
- `-include .includes/bootstrap.mk` added

### Build Infrastructure

- `.includes/bootstrap.mk` added (managed by `CPAN::Maker::Bootstrapper`)
- `.includes/update.mk`: `bootstrap.mk` added to `MANAGED_FILES`
- `builder`: fixed a bug where `CPAN::Maker::Bootstrapper` was being
  written with `>` (overwrite) instead of `>>` (append) to
  `build-requires`, which would silently drop any existing entries

### Dependencies

- **`Log::Log4perl`** added as a runtime dependency (previously only
  `Log::Log4perl::Level` was listed)
- `requires` file sorted for consistency
- `cpanfile` regenerated to reflect the above addition
- `deps.mk` regenerated: `CPAN::Maker::Role::Provides` added as a
  dependency of `CPAN::Maker`

## Bug Fixes

| Area | Fix |
|------|-----|
| `cmd_build` | `provides` file no longer deleted from project root after copy to build dir |
| `stage_distribution` | `provides` generation now uses the role's `create_provides`, fixing edge cases with embedded/multi-package modules |
| `write_makefile` | `BUILD_REQUIRES` is now correctly merged rather than overwritten, so project-level `build-requires` entries are honoured |
| `builder` | `>>` used instead of `>` when appending `CPAN::Maker::Bootstrapper` to `build-requires` |
| `test-requires` scanning | Modules provided by the distribution are now excluded from the `test-requires` list via `comm -23` against the `provides` file |

## Upgrade Notes

- Projects that relied on the `provides` file being automatically
  removed from the project root after a build will need to clean it up
  manually if required; it is now retained as a persistent artifact.
- The `get_provides` and `write_provides` methods are no longer
  defined directly on `CPAN::Maker` — they are consumed from
  `CPAN::Maker::Role::Provides`. Any subclasses overriding these
  methods should update accordingly.
- `Log::Log4perl` (not just `Log::Log4perl::Level`) is now a declared
  runtime dependency; ensure it is present in downstream environments.
